The UniApp SDK provides signaling APIs to initiate, accept, reject, cancel, and hang up audio and video calls. It also enables querying active group rooms, retrieving room access credentials, and restoring pending call invitations.

The SDK manages signaling metadata and room authentication credentials; it does not capture camera frames, process microphone audio, or render call UI components. Pass the returned `roomID`, `token`, and `liveURL` to your chosen real-time audio/video (RTC) engine, and manage hardware permissions, media tracks, network adaptation, and UI rendering within your application layer.

## Calling lifecycle

1. Initiate a one-on-one call using [Start a single call](/sdk/uniapp/calling/managing-calls/start-single-call), or launch a conference call using [Start a group call](/sdk/uniapp/calling/managing-calls/start-group-call).
2. When invited clients receive incoming signaling events, invoke [Restore pending call invitations](/sdk/uniapp/calling/retrieving-call-information/restore-pending-invitation) to reconstruct pending invitation state, then accept or reject.
3. The callee joins by calling [Accept a call](/sdk/uniapp/calling/managing-calls/accept-call) and passing the returned room credentials to their RTC engine.
4. Update UI displays based on signaling events; RTC media tracks are maintained directly by the media engine.
5. The caller can abort an unanswered invitation using [Cancel a call invitation](/sdk/uniapp/calling/managing-calls/cancel-call), while any active participant can terminate their session using [Hang up a call](/sdk/uniapp/calling/managing-calls/hang-up-call).

## Core data structures

| Structure | Description |
| --- | --- |
| `OpenIMSignalingInvitationInfo` | Metadata containing inviter, invitees, group ID, room ID, media type, timeout, and session type. |
| `OpenIMSignalingInviteResult` | Contains invitation details, RTC credentials, and busy user IDs returned when initiating a call. |
| `OpenIMSignalingAcceptResult` | Room connection credentials returned upon accepting an invitation. |
| `OpenIMSignalingGetRoomByGroupIDResult` | Active group call room ID and associated invitation payload. |

Promise resolution, event delivery, and state re-queries represent three distinct phases:

- A resolved Promise confirms that the signaling request reached OpenIMServer.
- Real-time signaling events inform other devices of the transition.
- Re-query APIs allow the app to synchronize state after returning to the foreground or reconnecting.

Calling events deliver raw payload strings without exposed internal schemas. Use events as invalidation signals to re-query strongly typed call data through the retrieval APIs. Identify call sessions using `roomID`, and track individual participants by combining `roomID` with user IDs. For event handling, see [Handle call events](/sdk/uniapp/calling/managing-calls/handle-call-events).
