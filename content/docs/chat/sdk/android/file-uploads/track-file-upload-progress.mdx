The Android SDK does not use a global file-upload listener. Pass an `OnPutFileListener` to each `uploadFile()` call. That listener receives progress, part completion, and final result callbacks for the current task.

```java
OnPutFileListener uploadListener = new OnPutFileListener() {
    @Override
    public void open(long size) {
        initializeUploadProgress(uploadTaskID, size);
    }

    @Override
    public void uploadID(String id) {
        bindSdkUploadID(uploadTaskID, id);
    }

    @Override
    public void uploadComplete(long fileSize, long uploadedSize, long storageSize) {
        updateUploadProgress(uploadTaskID, uploadedSize, fileSize);
    }

    @Override
    public void uploadPartComplete(long partNumber, long partSize, String partHash) {
        markPartComplete(uploadTaskID, partNumber, partSize, partHash);
    }

    @Override
    public void complete(long size, String url, long type) {
        completeUpload(uploadTaskID, size, url, type);
    }
};

OpenIMClient.getInstance().uploadFile(resultCallback, uploadListener, putArgs);
```

Use `open()` to initialize the total size, `uploadID()` to receive the SDK upload identifier, `uploadComplete()` for in-progress byte counts, `uploadPartComplete()` when one part finishes, and `complete()` for the final size, remote URL, and resource type. Most progress bars only need the progress and completion callbacks; process part details only when the product exposes them.

Generate a stable application-level `uploadTaskID` and capture it in the listener. Do not use the SDK upload ID, file name, or array position as the task's primary key. Give each task its own listener, and stop dispatching callbacks into destroyed page or account state.

For complete argument construction and error handling, see [Upload a file](/sdk/android/file-uploads/upload-file).
