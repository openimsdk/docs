OpenIM Android SDK uses listeners to report connection, synchronization, user, friendship, conversation, group, message, and calling changes. Listener setters on each manager use replacement semantics: a later call replaces the previous instance. Combine all callbacks in an application-level event center and register them once before login. Do not register them repeatedly from an Activity, Fragment, Compose screen, or feature component.

The connection listener is the exception. `OnConnListener` is passed to `initSDK()`; its complete handling contract is described in [Authenticate and manage a session](/sdk/android/getting-started/authenticate-and-manage-session).

## Register listeners centrally

The following entry point uses stable application-level listeners. Each listener should include all callbacks for its domain; detailed merge behavior remains on the page that owns each event.

```java
public final class OpenIMEventCenter {
    private final OpenIMClient client = OpenIMClient.getInstance();

    private final OnUserListener userListener = buildUserListener();
    private final OnFriendshipListener friendshipListener = buildFriendshipListener();
    private final OnConversationListener conversationListener = buildConversationListener();
    private final OnGroupListener groupListener = buildGroupListener();
    private final OnAdvanceMsgListener messageListener = buildMessageListener();
    private final OnCustomBusinessListener businessListener = buildBusinessListener();
    private final OnSignalingListener signalingListener = buildSignalingListener();

    public void registerBeforeLogin() {
        client.userInfoManager.setOnUserListener(userListener);
        client.friendshipManager.setOnFriendshipListener(friendshipListener);
        client.conversationManager.setOnConversationListener(conversationListener);
        client.groupManager.setOnGroupListener(groupListener);
        client.messageManager.setAdvancedMsgListener(messageListener);
        client.messageManager.setCustomBusinessListener(businessListener);
        client.signalingManager.setSignalingListener(signalingListener);
    }
}
```

The Android SDK does not expose remove or unset methods for these listeners. When signing out, switching accounts, or destroying the application state layer, stop dispatching into old account state and destroyed screens. Before the next login, replace each listener with the complete listener set for the new account.

Query APIs establish snapshots, and listeners merge subsequent changes. Query results, successful API callbacks, and event delivery are three independent stages and cannot replace one another.

## Handle initial synchronization

The synchronization lifecycle belongs to the application-level `OnConversationListener`. That listener must also include conversation-list, unread-count, and typing-status callbacks. The following example only highlights synchronization logic owned by this page.

```java
private OnConversationListener buildConversationListener() {
    return new OnConversationListener() {
        @Override
        public void onNewConversation(List<ConversationInfo> conversations) {
            mergeNewConversations(conversations);
        }

        @Override
        public void onConversationChanged(List<ConversationInfo> conversations) {
            mergeChangedConversations(conversations);
        }

        @Override
        public void onTotalUnreadMessageCountChanged(int total) {
            updateTotalUnreadCount(total);
        }

        @Override
        public void onConversationUserInputStatusChanged(String payload) {
            handleInputStatus(payload);
        }

        @Override
        public void onSyncServerStart(boolean reinstall) {
            setSyncState("syncing", 0, reinstall);
        }

        @Override
        public void onSyncServerProgress(long progress) {
            setSyncProgress(progress);
        }

        @Override
        public void onSyncServerFinish(boolean reinstall) {
            setSyncState("ready", 100, reinstall);
            reloadVisibleSnapshots();
        }

        @Override
        public void onSyncServerFailed(boolean reinstall) {
            setSyncState("failed", 0, reinstall);
        }
    };
}
```

When `reinstall` is `true`, treat local data as being rebuilt. Show a more complete synchronization state and avoid relying on old cache data until synchronization completes. `onSyncServerProgress` reports current progress. After completion, query the snapshots needed by visible screens again. On failure, record the error and wait for retry or connection recovery.

This page owns the complete handling contract for `onSyncServerStart`, `onSyncServerProgress`, `onSyncServerFinish`, and `onSyncServerFailed`. Synchronization state has no business entity key; isolate it by the current `OpenIMClient` singleton and signed-in user.
