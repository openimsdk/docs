HarmonyOS SDK 提供发起、接受、拒绝、取消和挂断通话所需的信令 API，也可以查询群组当前房间、重新获取入会凭据，并恢复尚未处理的邀请。

SDK 只负责信令和房间信息，不负责摄像头采集、远端音视频播放或通话界面。应用需要把 `roomID`、`token` 和 `liveURL` 交给所选实时音视频引擎，并自行处理权限、媒体轨道、弱网策略和界面状态。

## 基本流程

1. 发起方创建完整 `SignalingInvitationInfo`，通过[发起单聊通话](/sdk/harmony/calling/managing-calls/start-single-call)或[发起群聊通话](/sdk/harmony/calling/managing-calls/start-group-call)发起邀请。
2. 被邀请方在[处理通话事件](/sdk/harmony/calling/managing-calls/handle-call-events)中监听来电，或在应用启动恢复时通过[恢复待处理的通话邀请](/sdk/harmony/calling/retrieving-call-information/restore-pending-invitation)查询待处理邀请。
3. 接受方通过[接受通话](/sdk/harmony/calling/managing-calls/accept-call)取得房间凭据后连接媒体引擎；拒绝方通过[拒绝通话](/sdk/harmony/calling/managing-calls/reject-call)关闭来电界面。
4. 通话中按 `roomID` 合并邀请、参与者和挂断事件，参与者再结合用户 ID。
5. 发起方可以通过[取消通话邀请](/sdk/harmony/calling/managing-calls/cancel-call)取消未接通邀请，参与者可以通过[挂断通话](/sdk/harmony/calling/managing-calls/hang-up-call)挂断已建立通话。

`SignalingParticipantMetaData` 包含参与者的 `IMUser`；`OfflinePushInfo` 用于被邀请方离线时的通知。房间 Token 具有时效性，进入媒体房间前应使用当前邀请或重新查询得到的有效值。

Promise 成功、信令事件到达和房间查询是三个不同阶段。信令成功不表示媒体房间已经连接，也不表示其他参与端已经更新界面。
