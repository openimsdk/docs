Invoke `getFriendApplicationListAsApplicant()` to retrieve a paginated record of outgoing friend requests sent by the authenticated user. While `offset` and `count` are optional, specify them explicitly starting from `offset: 0` for stable paging.

## Parameters

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `offset` | `number` | No | Pagination offset index; pass `0` for the initial page. |
| `count` | `number` | No | Number of application records to fetch per page. |

## Code example

```uts
import { getFriendApplicationListAsApplicant } from '@/uni_modules/unix-openim-sdk'

const result = await getFriendApplicationListAsApplicant({
  offset: 0,
  count: 20,
})
const applications = result?.applications ?? []
```

## Return value

The Promise resolves with an `OpenIMFriendApplicationListResult | null` object containing `OpenIMFriendApplicationItem` elements in `applications`. For property definitions and review status constants, see [Get received friend applications](/sdk/uniapp/user/friend-applications/get-friend-application-list-as-recipient). This API does not filter by status; apply client-side filtering via `handleResult` as needed.

## State changes after the call

This is a read-only query that retrieves local snapshot records without emitting events. When incoming lifecycle changes arrive during active pagination, merge records using the composite key `fromUserID:toUserID`. For complete event registration logic, see [Get received friend applications](/sdk/uniapp/user/friend-applications/get-friend-application-list-as-recipient).
