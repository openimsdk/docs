## Debug OpenIMServer with an IDE

When developing or troubleshooting OpenIMServer deployed from source, you can attach an IDE debugger (such as JetBrains GoLand) to step through service logic. The following guide demonstrates how to debug the `openim-api` service step by step.

1. **Start all services:** Start the supporting dependencies and services by running:

   ```bash
   docker compose up -d
   mage start
   ```

2. **Locate the target service PID:** Inspect the console output to view all running OpenIM processes and their process IDs:

   ![Service process list](/assets/guides/gettingStarted/faq.assets/debug0.png)

   Find the specific service you want to debug, record its PID, and terminate that single process so the IDE can bind to its port:

   ```bash
   kill -9 854942          # Linux / macOS
   taskkill /PID 854942 /F  # Windows
   ```

3. **Locate the service entry point:** Service entry points reside under `open-im-server/cmd/`. For `openim-api`, the entry point file is `open-im-server/cmd/openim-api/main.go`.

4. **Configure IDE run/debug profile:** In GoLand, open `main.go`, click the run icon in the gutter, and select **Modify Run Configuration**:

   ![GoLand run configuration](/assets/guides/gettingStarted/faq.assets/debug1.png)

5. **Set program arguments:** Extract the exact startup flags from the original terminal output (for example: `-i 0 -c /data/open-im-server/config/`). Paste these flags into **Program arguments** and click **OK**:

   ![GoLand program arguments](/assets/guides/gettingStarted/faq.assets/debug2.png)

6. **Set breakpoints:** Set breakpoints in the code path you want to inspect (such as an API route handler or RPC call).

7. **Launch the debugger:** Start the application in **Debug** mode:

   ![Start GoLand debugging](/assets/guides/gettingStarted/faq.assets/debug3.png)

8. **Step through execution:** Send an API request from your client or curl. When execution hits the breakpoint, use the debugger to inspect variables, call stacks, and goroutine states:

   ![Paused at a breakpoint](/assets/guides/gettingStarted/faq.assets/debug4.png)
