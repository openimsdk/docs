如果界面需要让其他会话成员看到“消息已撤回”，使用 `revokeMessage()`，不要用普通删除替代。删除只影响当前账号侧可见性，见[批量删除消息](/sdk/wasm/message/managing-messages/delete-saved-messages)。修改已发送消息内容见[修改消息](/sdk/wasm/message/managing-messages/modify-a-message)。

## 撤回一条消息

`revokeMessage()` 接收消息所在的 `conversationID` 和目标 `clientMsgID`：

```ts
const { data } = await openimsdk.revokeMessage({
  conversationID,
  clientMsgID,
});

markMessageRevoked(data?.clientMsgID ?? clientMsgID);
```

Promise 成功后，当前应用可先把列表中具有相同 `clientMsgID` 的消息更新为撤回状态。在线客户端随后通过 `SdkEvent.OnNewRecvMessageRevoked` 收到撤回信息，接收端应根据事件里的 `clientMsgID` 更新对应气泡，而不是直接从列表中删除。

允许撤回的发送者、时间窗口和消息类型由 OpenIMServer 校验；调用失败时不要只在本地保留撤回展示。

SDK 同时保留 `SdkEvent.OnRecvMessageRevoked`。它是旧的单条撤回事件名；新代码优先监听 `OnNewRecvMessageRevoked`。维护既有项目时，应先确认当前部署实际触发的事件；如果只能收到旧事件，则用旧事件名替换下方注册项并复用同一个处理器，不要同时监听两个名称后重复合并同一次撤回。

## 返回结果

Promise 成功代表当前撤回请求已完成，不代表所有端界面已经更新。其他客户端收到撤回事件后，应使用 `clientMsgID` 找到并更新对应消息。

## 监听撤回事件

`OnNewRecvMessageRevoked` 的完整监听示例集中在本页。同步删除见[批量删除消息](/sdk/wasm/message/managing-messages/delete-saved-messages)，按用户批量删除见[删除群聊中指定用户的全部消息](/sdk/wasm/message/managing-messages/delete-user-messages)。

```ts
import { SdkEvent } from '@openim/wasm-client-sdk';

const handleMessageRevoked = ({ data }) => {
  markMessageRevoked(data.clientMsgID);
};

openimsdk.on(SdkEvent.OnNewRecvMessageRevoked, handleMessageRevoked);

function removeRevokeListener() {
  openimsdk.off(SdkEvent.OnNewRecvMessageRevoked, handleMessageRevoked);
}
```

`OnNewRecvMessageRevoked` 的 `data` 是 `RevokedInfo`。消息使用 `clientMsgID` 合并；`isAdminRevoke` 表示本次撤回是否由管理员执行，可用于选择合适的系统提示文案。组件卸载、退出登录或切换账号时调用 `removeRevokeListener()`。重新登录或重连后，先重新加载当前已有消息，再根据后续撤回事件更新对应消息。
