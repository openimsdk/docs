Android SDK 的 `SignalingManager` 提供发起邀请、接受、拒绝、取消、挂断、查询房间和同步通话状态所需的信令 API。它负责协调通话参与者、房间信息和通话生命周期，不负责采集摄像头画面、播放远端媒体流或渲染通话界面。

应用需要把 SDK 返回的 `roomID`、`token` 和 `liveURL` 交给所选的实时音视频媒体引擎，并自行处理 Android 权限、音视频设备、媒体轨道、弱网策略和界面状态。信令 API 不是一套完整的实时音视频媒体 SDK。

## 通话流程

1. 主叫方调用[发起单聊通话](/sdk/android/calling/managing-calls/start-single-call)或[发起群聊通话](/sdk/android/calling/managing-calls/start-group-call)建立呼叫。
2. 被叫方在通话事件监听中收到新邀请通知，选择接受或拒绝通话。
3. 接听方调用[接受通话](/sdk/android/calling/managing-calls/accept-call)，双方使用服务端返回的房间凭据接入 LiveKit 或 WebRTC 等实时音视频媒体引擎。
4. 通话过程中根据参与者状态、媒体流发布与自定义信令更新界面显示。
5. 通话未接通前主叫可[取消通话邀请](/sdk/android/calling/managing-calls/cancel-call)；通话建立后任意参与者均可[挂断通话](/sdk/android/calling/managing-calls/hang-up-call)。

## 核心数据

| 数据 | 说明 |
| --- | --- |
| `SignalingInvitationInfo` | 邀请人、被邀请人、群组、房间、媒体类型、超时时间、会话类型和业务扩展数据。 |
| `SignalingInfo` | 当前操作用户、事件中收到的完整邀请数据、参与者资料和可选的离线推送信息。 |
| `SignalingCertificate` | OpenIMServer 返回的 `roomID`、`token`、`liveURL` 和忙线用户列表。 |
| `RoomCallingInfo` | 按群组查询到的房间、邀请、当前参与者、群组和入会凭据。 |

`customData` 和自定义信令用于传递与当前通话相关的轻量、临时业务协商信息，不承担文件传输或长期状态保存。

## 状态更新与事件归属

发起、接受、拒绝、取消和挂断等操作需要明确区分异步 API 回调与实时事件通知。API 成功回调表示当前信令请求已被服务端受理；而各参与端的状态变更则通过事件监听器异步推送。

邀请生命周期、参与者进出房间、挂断和媒体流变化的完整 listener 统一见[处理通话事件](/sdk/android/calling/managing-calls/handle-call-events)；自定义信令见[发送自定义信令](/sdk/android/calling/sending-custom-signals/send-a-custom-signal)。

通话状态以 `roomID` 为全局合并标识；参与者状态则以 `roomID` 配合用户 ID 唯一定位。当需要恢复或确认当前房间状态时，可调用对应查询接口进行校准。
