消息页通常同时处理实时推送的新消息、应用进入后台后到达的消息、只在线投递的消息，以及首次进入会话时主动读取的历史消息。消息到达通过 `SdkEvent` 进入应用状态；历史列表通过 `getAdvancedHistoryMessageList()` 按 `conversationID` 分页读取。

在同一个 SDK 实例上注册事件处理器，并在组件卸载、退出登录或切换账号前用同一个函数引用调用 `off()`，避免同一批消息被重复处理。

## 消息类型

`SdkEvent.OnRecvNewMessages` 返回的是 `MessageItem[]`。每条消息可根据内容元素或消息类型选择对应的渲染方式，例如文本、自定义消息、@ 文本、图片、音频、视频和文件。

```ts
function renderMessage(message: MessageItem) {
  if (message.textElem) {
    return renderTextMessage(message);
  }

  if (message.atTextElem) {
    return renderMentionMessage(message);
  }

  if (message.customElem) {
    return renderCustomMessage(message);
  }

  if (message.pictureElem || message.soundElem || message.videoElem || message.fileElem) {
    return renderFileLikeMessage(message);
  }

  return renderUnsupportedMessage(message);
}
```

消息事件可能包含当前用户没有打开的会话。`MessageItem` 不直接提供 `conversationID`；应根据 `sessionType`、`sendID`、`recvID` 和 `groupID` 计算或查出目标会话，再按 `clientMsgID` 去重。

```ts
function messagesForCurrentConversation(messages: MessageItem[]) {
  return messages.filter(
    (message) => getConversationIDForMessage(message) === conversationID
  );
}
```

### 图片、音频、视频和文件消息

WASM SDK 使用不同的消息元素表示图片、音频、视频和普通文件。接收端无需重新上传文件，只需读取消息中已有的文件地址、大小、名称、时长或视频封面图等字段，并按界面规则展示。

如果产品需要一次发送多个文件，常见实现是连续发送多条文件消息，或发送一条自定义消息承载文件组数据。接收端渲染或更新消息时，应使用每条 `MessageItem` 的 `clientMsgID` 找到对应消息。

## 事件处理器

`SdkEvent.OnRecvNewMessages` 是聊天页面最常用的新消息事件。处理器中把当前会话的消息加入列表，并根据用户滚动位置决定是否自动滚到底部。

```ts
import { SdkEvent } from '@openim/wasm-client-sdk';

function handleNewMessages({ data }: { data: MessageItem[] }) {
  const messages = messagesForCurrentConversation(data);

  if (messages.length === 0) {
    return;
  }

  mergeMessagesByClientMsgID(messages);
  scrollToLatestMessageIfNeeded();
}

openimsdk.on(SdkEvent.OnRecvNewMessages, handleNewMessages);
```

应用处于后台时，新到达的消息一般会走 `SdkEvent.OnRecvOfflineNewMessages`，而不是前台常用的 `OnRecvNewMessages`。处理方式与实时新消息相同：筛选当前会话、按 `clientMsgID` 去重，并保持时间顺序。应用前后台状态由 SDK 包装层统一适配，业务页面只需处理对应的消息事件。

```ts
function handleOfflineMessages({ data }: { data: MessageItem[] }) {
  mergeMessagesByClientMsgID(messagesForCurrentConversation(data));
}

openimsdk.on(SdkEvent.OnRecvOfflineNewMessages, handleOfflineMessages);
```

发送方在 `sendMessage()` 或 `sendMessageNotOss()` 中把 `isOnlineOnly` 设为 `true` 时，接收端通过 `SdkEvent.OnRecvOnlineOnlyMessage` 收到这类只在线投递的消息。该事件每次提供一个 `MessageItem`。消息不会写入 SDK 本地消息存储，也不能通过历史消息接口回放，通常只适合临时提示或业务通知；是否展示在当前界面由产品规则决定。发送参数见[发送消息](/sdk/wasm/message/sending-messages/send-message)。

```ts
function handleOnlineOnlyMessage({ data }: { data: MessageItem }) {
  handleTransientMessages(messagesForCurrentConversation([data]));
}

openimsdk.on(SdkEvent.OnRecvOnlineOnlyMessage, handleOnlineOnlyMessage);

function removeMessageListeners() {
  openimsdk.off(SdkEvent.OnRecvNewMessages, handleNewMessages);
  openimsdk.off(SdkEvent.OnRecvOfflineNewMessages, handleOfflineMessages);
  openimsdk.off(SdkEvent.OnRecvOnlineOnlyMessage, handleOnlineOnlyMessage);
}
```

SDK 同时导出单条事件 `OnRecvNewMessage` 和 `OnRecvOfflineNewMessage`。新代码对普通和离线消息优先使用返回 `MessageItem[]` 的复数事件，便于统一批量处理；只在线消息使用正式的单条事件 `OnRecvOnlineOnlyMessage`。维护旧项目时，如果普通或离线消息只触发单条事件，应把 `data` 包装成数组，再复用相同的去重流程；不要同时监听同类消息的单数和复数事件名称，以免重复插入消息。

这些消息接收事件的完整监听示例集中在本页。普通和离线消息事件的 `data` 是 `MessageItem[]`，只在线消息事件的 `data` 是单个 `MessageItem`；都应先根据消息路由字段确定目标会话，再用“目标会话 + `clientMsgID`”找到并更新对应消息。重复事件不应插入第二条消息。组件卸载、退出登录或切换账号时调用 `removeMessageListeners()`。

当会话成员撤回消息时，接收端通过 `SdkEvent.OnNewRecvMessageRevoked` 得到更新。建议把对应气泡更新为撤回态，而不是直接从列表中删除；事件处理器和清理方式见[撤回消息](/sdk/wasm/message/managing-messages/revoke-a-message)。

## 首次进入会话时读取历史

事件只负责推送新到达的消息。首次进入会话、向上翻页或需要补齐断线期间的列表时，应另外读取历史消息。分页参数、调用示例和 `AdvancedMessageListResult` 结构见[加载历史消息](/sdk/wasm/message/retrieving-messages/load-older-messages)。

历史查询不会触发新消息事件；事件和分页结果可能包含同一条消息，因此两条路径都必须使用相同的 `clientMsgID` 去重规则。

## 将群聊会话标记为已读

用户进入群聊并看到最新消息后，可以清理该会话的未读数。这个操作处理的是会话未读数，不等同于群消息成员级已读回执；调用方式和状态同步见[标记会话已读](/sdk/wasm/conversation/managing-conversations/mark-conversation-read)。

会话列表和总未读角标分别通过[获取会话列表](/sdk/wasm/conversation/retrieving-conversations/retrieve-conversation-list)和[维护总未读数](/sdk/wasm/conversation/managing-conversations/get-total-unread-count)中的事件处理器做最终同步。

如果事件注册在全局消息状态层，不要在每次进入同一个群聊页面时重复注册全局处理器。首次进入会话、重新登录或重连后，先分页读取当前已有的历史消息，再把后续事件带来的消息变化合并到列表中；不要把事件到达视为某次历史查询或已读调用的完成回调。

## 验证接收流程

- 在另一个已登录账号中向目标 `groupID` 发送消息，确认当前浏览器通过 `SdkEvent.OnRecvNewMessages` 收到消息。
- 确认回调使用当前群聊的 `conversationID` 过滤消息，并且列表按 `clientMsgID` 去重后只渲染一次。
- 将应用切换到后台后，再由另一端发送消息，确认当前端通过 `SdkEvent.OnRecvOfflineNewMessages` 收到；回到前台后确认普通新消息事件继续正常工作。
- 发送方将 `isOnlineOnly` 设为 `true` 后，确认接收端通过 `SdkEvent.OnRecvOnlineOnlyMessage` 收到，且该消息不会进入本地消息存储或历史列表。
- 撤回一条群消息，确认接收端通过 `SdkEvent.OnNewRecvMessageRevoked` 把对应 `clientMsgID` 更新为撤回态。
- 进入群聊后调用 `markConversationMessageAsRead(conversationID)`，确认会话未读数和总未读角标随事件更新。
