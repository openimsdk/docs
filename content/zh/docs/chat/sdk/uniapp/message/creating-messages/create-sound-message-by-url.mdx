`createSoundMessageByURL()` 适用于音频已经由业务上传服务取得远端 URL 的场景。传入的信息应与实际上传结果一致。

## 参数说明

| 参数 | 类型 | 是否必填 | 说明 |
| --- | --- | --- | --- |
| `uuid` | `string` | 否 | 音频资源唯一标识，优先使用上传结果返回的值。 |
| `soundPath` | `string` | 否 | 原始本地路径；只有远端资源时可以传空字符串。 |
| `sourceUrl` | `string` | 否 | 已上传音频的可访问地址；创建 URL 型音频消息时应提供。 |
| `dataSize` | `number` | 否 | 音频文件大小，单位为字节。 |
| `duration` | `number` | 否 | 音频时长，单位为秒。 |

```uts
import { createSoundMessageByURL } from '@/uni_modules/unix-openim-sdk'

const message = await createSoundMessageByURL({
  uuid: uploaded.uuid,
  soundPath: '',
  sourceUrl: uploaded.url,
  dataSize: uploaded.size,
  duration: 12,
})
if (message == null) return
```

虽然接口类型允许这些字段为空，但可播放的 URL 型音频消息至少需要有效的 `sourceUrl`，并应同时提供真实的文件大小和时长。不要使用过期的临时下载地址。

Promise 成功只创建待发送对象。后续使用[发送已上传的媒体消息](/sdk/uniapp/message/sending-messages/send-message-not-oss)，避免再次上传音频。
