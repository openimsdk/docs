The standalone file upload API uploads user avatars, group avatars, profile attachments, or other business assets directly to object storage. This upload operation is decoupled from the message lifecycle and does not create messages or update user profiles automatically.

## Code example

```java
File file = new File(localPath);
PutArgs args = new PutArgs(file.getAbsolutePath());
args.name = file.getName();
args.cuase = "user-avatar";

OpenIMClient.getInstance().uploadFile(
    new OnBase<String>() {
        @Override
        public void onSuccess(String result) {
            // result is the final JSON string result of the upload request.
        }

        @Override
        public void onError(int code, String error) {
            // code and error describe the failure.
        }
    },
    new OnPutFileListener() {
        @Override
        public void open(long size) {
            // size is the total byte size of the file to upload.
        }

        @Override
        public void uploadID(String id) {
            // id is the server-assigned upload task identifier.
        }

        @Override
        public void uploadComplete(long fileSize, long streamSize, long storageSize) {
            // File byte transfer is complete.
        }

        @Override
        public void complete(long size, String url, long type) {
            // url is the accessible remote resource URL.
        }
    },
    args
);
```

## Parameters

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `base` | `OnBase<String>` | Yes | Callback delivering the final success or error response of the upload request. |
| `listener` | `OnPutFileListener` | Yes | Listener tracking file chunks, hashing progress, upload status, and completion. |
| `putArgs.filepath` | `String` | Yes | Local absolute file path accessible to the Android application. |
| `putArgs.name` | `String` | Yes | Upload file name. Defaults to the input path; customize as needed. |
| `putArgs.cuase` | `String` | No | Business upload reason tag. Matches the exact `cuase` field declared in the Android SDK's `PutArgs`. |

## Return value

The `onSuccess` callback receives the raw completion string, while the `complete(long size, String url, long type)` callback on `OnPutFileListener` delivers the final remote URL, total file size, and content type.

Use the returned URL in subsequent API calls to update user avatars, configure group avatars, attach media to messages, or link attachments. Uploading writes binary data to object storage but does not update domain profiles or dispatch chat messages automatically.

## Progress and lifecycle callbacks

`OnPutFileListener` provides real-time chunk and transmission lifecycle events:

| Callback | Parameters | Description |
| --- | --- | --- |
| `open` | `size` | File stream opened; reports total file size in bytes. |
| `partSize` | `partSize`, `num` | Chunking configuration reporting individual chunk size and total chunk count. |
| `hashPartProgress` | `index`, `size`, `partHash` | Checksum calculation completed for a single chunk. |
| `hashPartComplete` | `partsHash`, `fileHash` | Complete checksum calculation finished across all chunks. |
| `uploadID` | `uploadID` | Server upload session ID assigned. |
| `uploadPartComplete` | `index`, `partSize`, `partHash` | Chunk upload confirmed by the storage service. |
| `uploadComplete` | `fileSize`, `streamSize`, `storageSize` | Data transmission finished, delivering final file, stream, and storage sizes. |
| `complete` | `size`, `url`, `type` | Full upload pipeline finished; delivers the remote resource URL. |
