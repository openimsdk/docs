The OpenIM React Native SDK delivers native instant messaging and real-time communication capabilities for cross-platform mobile applications. Packaged as `@openim/rn-client-sdk`, it supports both Bare React Native CLI projects and Expo custom development client environments. Developers access SDK initialization, user relationships, conversations, groups, messages, audio/video call signaling, and realtime event listeners through the singleton `OpenIMSDK` instance.

## Integration workflow

1. Install `@openim/rn-client-sdk` into your React Native project and link native dependencies (or run `npx expo prebuild` to generate the native projects in Expo).
2. Retrieve the current user's `userID`, authentication token, and the OpenIMServer HTTP and WebSocket endpoints from your backend.
3. Follow [Authenticate and manage a session](/sdk/react-native/getting-started/authenticate-and-manage-session) to initialize the SDK and register network connectivity listeners.
4. Call `login()` to authenticate the user and wait for the `onConnectSuccess` event.
5. Once authenticated, invoke user, conversation, group, message, or RTC calling APIs as needed.
6. Register business event listeners and merge incoming incremental updates into your application state using stable primary identifiers.

Import `OpenIMSDK` via `import OpenIMSDK from '@openim/rn-client-sdk'` to access all SDK capabilities across your application.

## Client state reconciliation guidelines

When receiving asynchronous events from the SDK, update local application state using these primary identifiers:

- **Conversation**: `conversationID`
- **Conversation group**: `conversationGroupID`
- **Group**: `groupID`
- **Group member**: `groupID:userID`
- **Friend & Blacklist**: `userID`
- **Message**: `clientMsgID` (qualified with `conversationID` when necessary)
- **Call**: `roomID` (using `userID` for individual participant states)

Never use array indexes or display names as reconciliation keys. Treat Promise resolution, incoming push events, and re-query reconciliation as three distinct phases in your UI architecture.
