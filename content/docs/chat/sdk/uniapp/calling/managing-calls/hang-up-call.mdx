Once a call is connected, any active participant can invoke `signalingHungUp()` to hang up and terminate their participation.

## Parameters

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `invitation` | `OpenIMSignalingInvitationInfo` | Yes | The complete invitation object associated with the active call. |

Supply the complete `invitation` payload corresponding to the active call session. Ensure `roomID` matches the active media channel.

## Code example

```uts
import { signalingHungUp } from '@/uni_modules/unix-openim-sdk'

await signalingHungUp({ invitation })
```

## Return value

The Promise resolves with `void` once the hang-up signal is submitted to OpenIMServer.

## State changes after the call

A resolved Promise confirms that the hang-up signaling completed. The client must still stop local audio/video capture, exit the media engine room, and release hardware resources (camera and microphone). Identify and clean up session state across components using `roomID`. For handling remote hang-up notifications, see [Handle call events](/sdk/uniapp/calling/managing-calls/handle-call-events).
