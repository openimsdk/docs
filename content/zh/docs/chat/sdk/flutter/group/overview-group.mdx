OpenIM 的多人聊天场景通过群组承载共享资料、成员关系与权限管控。`groupID` 是群组的唯一标识，无论是发送群消息、读取群资料、管理成员还是处理入群申请都需要使用它。当前用户聊天列表中的群会话仍由 `conversationID` 统一管理，两者不可混淆。

## 核心数据类型

| 类型 | 用途 |
| --- | --- |
| `GroupInfo` | 群名称、头像、公告、群主、验证配置、成员数和扩展字段。 |
| `GroupMembersInfo` | 用户在指定群内的昵称、角色、禁言和入群信息。 |
| `GroupApplicationInfo` | 入群申请及处理状态。 |

群角色使用 `GroupRoleLevel`：普通成员为 `20`，管理员为 `60`，群主为 `100`。前端可据此控制入口，但最终权限由 OpenIMServer 校验。

## 状态更新

群组相关的状态通知包含加入群组、退出群组、群资料变更以及群解散。各类回调通过应用唯一的 `OnGroupListener` 集中注册，客户端统一以 `groupID` 为合并标识更新本地群组缓存。

群成员变更事件请参考[群成员查询概览](/sdk/flutter/group/retrieving-group-members/overview-retrieving-group-members)，申请事件请参考[入群申请概览](/sdk/flutter/group/group-applications/overview-group-applications)。Future 完成、随后到达的事件通知和重新查询校准属于三个独立阶段，应分别妥善处理。

OpenIM Flutter SDK 的群组 API 聚焦于群资料、成员关系与权限管理。公开展现、复杂群目录和超大规模群聊的容量治理通常由业务后端与 OpenIMServer 配置协同实现。
