`signalingGetRoomByGroupID()` takes a group ID, not a custom `roomID`.

```java
OpenIMClient.getInstance().signalingManager.signalingGetRoomByGroupID(
    new OnBase<RoomCallingInfo>() {
        @Override
        public void onSuccess(RoomCallingInfo room) {
            if (room.getRoomID() != null && !room.getRoomID().isEmpty()) {
                renderParticipants(room.getParticipant());
            }
        }

        @Override
        public void onError(int code, String error) {
            showNoActiveGroupCall();
        }
    },
    groupID
);
```

The success callback returns a `RoomCallingInfo` snapshot containing the room ID, original invitation, participants, group ID, token, and connection address. Account profiles, group member profiles, and group profiles inside participant data come from different sources and must not overwrite one another.

If no group call is active, treat an error or empty room as “no call to restore” and discard old credentials. Even when your group call uses a custom room ID, this method still receives `groupID`.
