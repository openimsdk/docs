The OpenIM Flutter SDK identifies users by their `userID`. When implementing user profile cards, friend discovery, contact directories, or blocklists, differentiate between public user profiles, friend relationships maintained by the current account, and blocklist states.

Group member rosters, in-group nicknames, group roles, and membership administration belong to the group domain; see [Retrieving group members overview](/sdk/flutter/group/retrieving-group-members/overview-retrieving-group-members).

## User data models

OpenIM returns distinct user data structures depending on the operational context:

| Model | Target Use Case | Associated Guides |
| --- | --- | --- |
| `UserInfo` | Currently logged-in user profile, account settings, self avatar, nickname, and global message reception settings. | [Get self profile](/sdk/flutter/user/retrieving-and-updating-user-information/get-self-profile), [Update self profile](/sdk/flutter/user/retrieving-and-updating-user-information/update-self-profile) |
| `PublicUserInfo` | User search, friend discovery candidates, stranger profile cards. | [Retrieve users](/sdk/flutter/user/retrieving-users/retrieve-users) |
| `FriendInfo` | Friend list entries for the current user, friend remarks, and friendship custom extensions. (Note: the Dart model does not contain `isPinned`). | [Get friend list with pagination](/sdk/flutter/user/friends/get-friend-list-page), [Get friends info](/sdk/flutter/user/friends/get-friends-info) |
| `BlacklistInfo` | Users blocked by the current account. | [Retrieve a list of blocked users](/sdk/flutter/user/moderating-a-user/retrieve-a-list-of-blocked-users), [Block a user](/sdk/flutter/user/moderating-a-user/block-user), [Unblock a user](/sdk/flutter/user/moderating-a-user/unblock-user) |
| `UserStatusInfo` | Real-time presence status and active platform indicators. | [Subscribe to user status](/sdk/flutter/user/retrieving-and-updating-user-information/subscribe-user-status), [Get subscribed user status](/sdk/flutter/user/retrieving-and-updating-user-information/get-subscribed-user-status) |

A single `userID` can exist simultaneously in public directories, the friend roster, the blocklist, and group rosters. Prioritize `FriendInfo` when rendering contacts; use `PublicUserInfo` when displaying stranger profiles; and use `GroupMembersInfo` in group contexts. For conversation list titles and chat headers, use `ConversationInfo.showName`.

## State management and listeners

Listen to and merge user domain events within their respective capability handlers:

- Current user profile updates: see [Update self profile](/sdk/flutter/user/retrieving-and-updating-user-information/update-self-profile).
- Friend application changes: see [Get friend application list as recipient](/sdk/flutter/user/friend-applications/get-friend-application-list-as-recipient).
- Friendship additions, deletions, and updates: see [Get friend list with pagination](/sdk/flutter/user/friends/get-friend-list-page).
- Blocklist modifications: see [Block a user](/sdk/flutter/user/moderating-a-user/block-user).
- Presence status changes: see [Subscribe to user status](/sdk/flutter/user/retrieving-and-updating-user-information/subscribe-user-status).

`UserManager` and `FriendshipManager` each maintain a single listener instance in the Flutter SDK. Assemble all required callbacks centrally in an application-level state provider and register each listener once to prevent individual Widgets from overwriting one another.
