OpenIM React Native SDK represents every message using the `MessageItem` structure. Creating a message creates a client-side `MessageItem` ready to be dispatched; to send it to a one-to-one user or a group, call the appropriate sending API. Incoming messages, queries, and lifecycle state changes (deletion, revocation, modification, read receipts) are processed through their respective APIs and event listeners.

Message lists rely on `clientMsgID` as the primary identifier to deduplicate, update, and locate individual messages. Note that `MessageItem` does not contain a `conversationID` property; obtain the message's conversation context from active conversation state, history query parameters, or event metadata.

## Message lifecycle workflow

| Stage | Capability | Description |
| --- | --- | --- |
| Create | `create*Message()` | Initializes a local `MessageItem` instance ready for sending without calling the server. |
| Send | [Send message](/sdk/react-native/message/sending-messages/send-message), [Send uploaded media message](/sdk/react-native/message/sending-messages/send-message-not-oss) | Dispatches the message to a one-to-one or group conversation. |
| Receive | Message events | Receives real-time, offline, and online-only incoming messages. |
| Query | History, lookup by ID, search | Retrieves and paginates historical messages from local cache and server. |
| State changes | Revoke, delete, modify, read receipts | Reconciles message status transitions via API results and incremental events. |

## MessageItem structure

All creation, transmission, reception, and query APIs return `MessageItem` objects. Common core properties include:

| Field | Type | Description |
| --- | --- | --- |
| `clientMsgID` | `string` | Unique client-generated message ID, used for deduplication, updates, and indexing. |
| `serverMsgID` | `string` | Unique server-assigned message ID. |
| `sessionType` | `SessionType` | Conversation type, distinguishing one-to-one chats from group chats. |
| `sendID` | `string` | Sender user ID. |
| `recvID` | `string` | Recipient user ID for one-to-one messages. |
| `groupID` | `string` | Target group ID for group messages. |
| `contentType` | `MessageType` | Message content type, determining which payload element to render. |
| `createTime` | `number` | Timestamp when the message object was created. |
| `sendTime` | `number` | Timestamp when the message was dispatched. |
| `seq` | `number` | Server-assigned message sequence number. |
| `senderPlatformID` | `Platform` | Platform identifier of the sending client. |
| `status` | `MessageStatus` | Transmission status of the message. |
| `isRead` | `boolean` | Read receipt state for the message. |
| `senderNickname` | `string` | Display nickname of the sender. |
| `senderFaceUrl` | `string` | Avatar URL of the sender. |
| `offlinePush` | `OfflinePush` | Offline push notification payload configuration. |
| `content` | `string` | Serialized message payload. For UI rendering, read the specific element corresponding to `contentType`. |
| `ex` | `string` | Custom global extension field synchronized across clients. |
| `localEx` | `string` | Custom local-only extension string stored exclusively on the current device. |

Message content payloads are stored in specific element fields matching `contentType`:

| Content payload | Field |
| --- | --- |
| Text, rich text, and Markdown | `textElem`, `advancedTextElem`, `markdownTextElem` |
| Image, audio, video, and file | `pictureElem`, `soundElem`, `videoElem`, `fileElem` |
| Mention (@) message | `atTextElem` |
| Quote reply message | `quoteElem` |
| Merged forward | `mergeElem` |
| Business card, location, and face/sticker | `cardElem`, `locationElem`, `faceElem` |
| Custom business message | `customElem` |
| System notification, typing indicator, attached info | `notificationElem`, `typingElem`, `attachedInfoElem` |

All payload elements are optional fields on `MessageItem`. Inspect `contentType` first to determine which element to parse and render.

## Event handling

Complete event listener implementations and registration patterns are documented on their dedicated pages:

- New messages, offline messages, and online-only messages: `OnRecvNewMessage`, `OnRecvOfflineNewMessage`, `OnRecvOnlineOnlyMessage`. See [Receive messages](/sdk/react-native/message/receiving-messages/receive-messages).
- Custom business messages: `OnRecvCustomBusinessMessage`. See [Receive custom business messages](/sdk/react-native/message/receiving-messages/receive-custom-business-messages).
- Message deletion: `OnMsgDeleted`. See [Delete saved messages](/sdk/react-native/message/managing-messages/delete-saved-messages).
- Message revocation: `OnNewRecvMessageRevoked`. See [Revoke a message](/sdk/react-native/message/managing-messages/revoke-a-message).
- Message modification: `OnMessageModified`. See [Modify a message](/sdk/react-native/message/managing-messages/modify-a-message).
- Group message read receipts: `OnRecvGroupReadReceipt`. See [Send group read receipts](/sdk/react-native/message/managing-read-status/send-group-read-receipts).
- Typing status changes: `OnInputStatusChanged`. See [Change input states](/sdk/react-native/message/composing-messages/change-input-states).
