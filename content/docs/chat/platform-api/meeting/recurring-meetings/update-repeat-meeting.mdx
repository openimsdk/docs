Update a recurrence definition and the future instances generated from it.

## HTTP request
```bash
POST {API_ADDRESS}/rtc-meeting/update_repeat_meeting
```

## Request body
| Parameter | Required | Type | Description |
| --- | --- | --- | --- |
| repeatMeetingID | Yes | string | Recurring meeting ID. |
| updatingUserID | Yes | string | User performing the update. |
| creatorDefinedMeetingInfo | Yes | CreatorDefinedMeetingInfo | Updated shared meeting information. |
| setting | Yes | MeetingSetting | Updated shared settings. |
| repeatInfo | Yes | MeetingRepeatInfoReq | Updated recurrence rule. |

## Response
Returns updated `data.repeatMeeting` and the affected `data.generatedMeeting`.

## Permissions and limits
- Available only in OpenIM Enterprise.
- Do not assume completed or historical instances are rewritten.
